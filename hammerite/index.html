A level editor that runs inside your game.

Brush-based level editing for Godot, with a retro radiosity lightmapper and sound propagation through the rooms you carve. There is no edit-save-run loop: you edit and test in the same running game.

Edit and test in the same game

Hammerite runs inside the game itself, so the level you are editing is the level you are playing. You do not need to save, export or reload anything before trying a change.

The usual loop

  1. Edit the level
  2. Save it
  3. Run the game
  4. Walk back to the spot
  5. Test
  6. Quit, and start over

With Hammerite

  1. Edit the level
  2. Test

Carve a doorway and walk through it. Bake the light and look at it from where you stand. Close a door and hear the guard beyond it go quiet.

Subtractive workflow

Solid is the default. Air brushes carve rooms out of it, and the compiler works out the rest: which air is one room, where rooms open into each other, and which walls are visible. Overlap brushes to extend a space, and abut them to divide one.

Lighting, sound and navigation all use the same compiled world, so a room is lit, heard and walkable as soon as it is carved. There is more about this in Hammerite's subtractive workflow and compiler.

Retro radiosity lighting

A GPU radiosity lightmapper in the spirit of the classic brush-based games. Light bounces, takes colour from the walls and collects in the corners.

Every surface has four light slots, so lamps can flicker, dim and switch on and off at runtime without rebaking. For example a flickering torch, a chandelier that goes out all at once, or lightning flashing in every window. After an edit, a quick bake lights only the walls that changed.

Sound propagation

Sound travels through doorways and windows instead of through walls, so you hear it from the opening it comes through. A closed door on the way muffles it, and AI hears sounds the same way.

Reverb comes from each room's size and surfaces. Rain and wind are all around you outdoors, and indoors you hear them through the nearest windows, muffled by the roof.

Shipping the editor

The editor comes with its own manual under Help. Games made with Hammerite may ship it, so players can make maps too, royalty-free.

Navigation

Walkable ground and traversal links come straight from the carved rooms, as Godot navigation meshes.

Four addons, one native library

Each is a standalone Godot addon, and nothing in them depends on a particular game. All four are C++, built into one GDExtension library, so there is no GDScript of Hammerite's to compile when your game starts. The docs have the guides and the full API reference.

AddonWhat it doesPackage
hammerite-coreData model, subtractive compiler, runtime scene, radiosity lightmapperruntime, full
hammerite-audioSound propagation through the rooms, weather, reverb and AI hearingruntime, full
hammerite-navWalkable ground, traversal links and Godot navigation meshesruntime, full
hammerite-editorThe in-game level editorfull

Two packages: full has everything, and runtime leaves out the editor, for a game whose players never open it. The library is built for macOS (Apple silicon and Intel), Windows and Linux on x86-64. There is no web export.

Native code is what keeps the edit-test loop quick on a big level. In 2.0, 256 rooms compile in 303 ms instead of 626, a one-brush edit recompiles in 25 ms instead of 42, and a large stealth level's navigation builds in 2.8 s instead of 5.7.
