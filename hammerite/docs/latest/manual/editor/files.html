Map files

Do How
Start an empty map File → New Map
Open a map File → Open Map… (Cmd O)
Save File → Save Map (Cmd S)
Save under a new name or format File → Save Map As… (Cmd Shift S)
Save edited prefabs File → Save Modified Prefab Sets
Migrate what Hammerite 1.x saved File → Migrate 1.x Resources…
Leave the editor and return to the game File → Close Editor

The file dialogs browse the whole disk. A map that has never been saved asks for a name on Cmd S.

Opening or starting another map with unsaved changes asks whether to save them first.

Backups and autosave

  • Each save keeps the file it replaces beside it as level.hmap.bak. To go back one save, rename it to level.hmap.
  • A save writes a new file first and only then puts it in place, so a crash while saving leaves the old file whole.
  • Every five minutes with unsaved changes, the map is written to level.autosave.hmap beside it. A map not saved yet autosaves to the game's user folder. Saving deletes the autosave.
  • Opening a map whose autosave is newer than the file offers to open the autosave instead. It opens as the map with its changes unsaved: save to keep them.

Formats

Extension What it is Where it can live
.hmap a Hammerite map: data only anywhere
.tres, .res a Godot resource inside the game's project only

Use .hmap for maps you share or download. It holds values only, so opening one cannot run code. A .tres or .res can, which is why the editor refuses one from outside the project.

To convert a map, open it and Save Map As… with the other extension.

Maps from TrenchBroom

Importing is done once, in the Godot editor: Project → Tools → Import .map File… reads a .map, as TrenchBroom, J.A.C.K. and the Radiants save it, and writes it into the project as a .hmap, res://maps/<name>.hmap unless you choose another. Open that here. Entity definitions is what the game's entities are, as its level's are: its entity set, a folder of scenes or an FGD, which may tell the importer what the game wants of each entity. Tick Quake's conventions for a map made with id's or Valve's art and entities.

  • A .map builds walls in empty space; Hammerite carves rooms out of rock. The space around the map is filled back in as solid brushes, on a layer named Void filled on import that starts hidden. Leave them: they are the rock outside your map.
  • Everything inside the map's walls comes in as one room, one air brush. Select it and choose Selection → Divide into Rooms: it is divided at every doorway and window - a hole through a wall that is larger than the hole - and wherever a door closes an opening, into air brushes that overlap within a room and abut at each doorway, so each doorway is a portal. Undo puts the one brush back. Where it divided wrongly or not at all, see Dividing a map into rooms. The command divides any air brush that spans several rooms, not only an imported one.
  • A map that leaks - with a gap in its outside walls - comes in with the space round it still open, and the message log says so. Close the gap and import it again.
  • TrenchBroom's layers and groups come in as layers and groups, hidden and locked as they were. A layer TrenchBroom omits from export is left out. A group inside another group becomes part of the outer one, since a group in Hammerite holds no groups.
  • Which entities come in, and as what, is your game's choice; the message log names the kinds left out. Skip, hint and other tool brushes are left out of the world. A clip brush comes in as a wall nobody sees, a clip entity, where the game has the map tools' entity types: Hammerite's own sets have them, as do a TrenchBroom or func_godot game's ported entities. It is drawn striped and see-through, purple or in the colour of what it stops, and left out of the bake. Caulk and nodraw brushes are walls like any other.

Missions from DromEd

Project → Tools → Import DromEd Mission… in the Godot editor reads a Thief, Thief 2 or System Shock 2 mission, a .mis, and writes it into the project as a .hmap, as a .map is.

  • DromEd carves rooms out of solid as Hammerite does, so each brush comes in as the brush it was, in the order DromEd applied them. Flood brushes become water.
  • A face keeps the mission's own texture where your project has it, in Textures - fam/city/wall7 is looked up as dark_city_wall7, or !dark_city_wall7 where it is see-through - and takes the one named in Other faces where it has not. Unpack them first: Project → Tools → Unpack Game Textures… opens the game's RES/fam.crf and RES/obj.crf, or a fan mission's zip, and writes their textures to res://textures/dark, where the import looks. A texture's colour 0 is see-through, as the game draws it, and the glow a NewDark material (.mtl) gives it is its emission.
  • The mission's lights come in, a flickering or pulsing one as a light that can change, and a spotlight as a spot, aimed the way its object faces, with its cone and its soft edge. A spotlight with ambient light is a spot and a point light together. Its other objects, and its guards' patrols, do not: how they map onto your game is your game's to say.
  • The gamesys the mission names is read from beside it, for which material each texture is. Without one, the import still works and the message log says so.
  • A mission saved without its brushes - as Looking Glass shipped their own - is refused: all that is left in it is the compiled world, which would come in as a brush for every convex piece of it.

Files from Hammerite 1.x

A .tres, .res or scene saved by Hammerite 1.x does not open in 2.0 until it is migrated. File → Migrate 1.x Resources… does it from the editor:

  1. It looks in the project (res://) first. To look somewhere else, type a res:// or user:// folder into Folder and press Enter, or press Choose….
  2. It lists the files it would migrate, the ones it cannot with why, and how many need nothing. Nothing is written yet.
  3. Migrate rewrites them, keeping each original beside it as name.tres.bak unless you untick that, and lists what it did. A file it cannot migrate is left as it was.

The dialog works from the keyboard: Tab moves between its controls, Enter presses the one in focus, Esc closes it. A game that binds a pad's buttons to Godot's ui_accept and ui_cancel drives it from the pad too.

While the game cannot start for its 1.x files, use the same dialog in the Godot editor: Project → Tools → Migrate Hammerite 1.x Resources.... The Godot editor rescans the project when it is done; after migrating from the game, it notices the changed files when you switch back to it.

What else is saved

  • A worldrep cache beside the map, named after it: level.worldrep.hcache for level.hmap, level.worldrep.res for a resource. It holds the carved world so the map opens without carving it again. Saving writes the cache of the variant in effect; other variants get a file with their number in the name. Deleting a cache is safe: the map is carved on load instead.
  • Every prefab set you changed.
  • A record of what the map names that the game provides: textures, models, sounds.

When the game has changed

When you open a map, the editor checks what it names against what the game provides now: a texture gone, a model now provided by something else. Each change is listed in the Problems panel, under Changed in the game since saving, until you save the map.
