HammeriteAudioRuntime

Audio. Inherits RefCounted

Process-wide access to the audio managers, the game's sound-type table, and the bake.

The HammeriteAudio autoload is the friendly front door, but it cannot be the place this state lives. An autoload is only an identifier inside a running scene tree: a node that mentions one by name will not even compile in a headless tool script, which would put every node in this addon - and everything that tests them - out of reach of the test runner.

So the registry is static, here, and the autoload delegates to it. Same lifetime, same single instance, no dependency on the scene tree existing. A game reaches for this directly only where there is no tree to reach the autoload through: a headless bake, a CI run, a tool script.

Native since 2.0 (#269): its static variables are the static methods get_<name>() and set_<name>(), since GDScript reaches no static property of a native class, and GRAPH_KEY, AMBIENCE and SOUND_FILE are graph_key(), ambience() and sound_file(). Its inner class Changes is HammeriteAudioRuntimeChanges.
