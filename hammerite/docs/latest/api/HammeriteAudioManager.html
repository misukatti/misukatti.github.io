HammeriteAudioManager

Audio. Inherits RefCounted

One map's sound: plays sounds through its audio graph, sets the reverb, and tells listeners.

Manages all acoustic propagation logic, sound playback, and audio stream management. Kept in the view's runtime data (HammeriteMap3D.get_runtime_data()) by the HammeriteAudio autoload, which makes a new one whenever the map or its variant changes; reach it with HammeriteAudio.get_manager(node) rather than holding on to one.

Responsibilities: - Sound submission API for entities - AudioStreamPlayer3D pool management (dynamic allocation) - AudioStream caching with resource names as keys - All propagation calculations (zone detection, portal finding, path queries) - Position && volume updates each frame - Reverb application based on listener position - Multi-source sound support

============================================================================== INNER CLASSES - Type-safe sound data containers ==============================================================================

What one sound is and is doing. Taken from the HammeriteAudioSoundSpec it was created from, and the manager's own from then on: the spec is read once and never held, so a caller may reuse it.

Native since 2.0 (#269): BUS_NAME is bus_name(), and its inner sound classes are HammeriteAudioManagerSoundData and the two that extend it.
