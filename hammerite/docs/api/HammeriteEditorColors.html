HammeriteEditorColors

Editor. Inherits Resource

Every colour the editor draws the WORLD in: the viewports, the overlays, the gizmos (#48).

One resource rather than a field per colour on HammeriteMapEditorSettings and a const in whichever script happened to need it. They were in three places - the settings, private vars on the drawing nodes, and bare Color literals at the point of use - so there was no palette to look at, nothing a game could re-colour wholesale, and no way to tell a deliberate choice from a default nobody had thought about. Not the editor's own chrome. Panels, buttons, text and menus are HammeriteEditorTheme, which is a Theme and lives in the UI. The division is what the colour is FOR: this is the map, that is the tool looking at it. Changing one while the editor is up shows wherever it is drawn every frame; call HammeriteMapEditor.apply_colors() for the rest, which take theirs when they are built.

var selected_wireframe: Color = Color(0.6039216, 0.8039216, 0.19607843, 1)

Three greens for one idea. Left as they were rather than quietly unified, since that is a look to change on purpose and not in a move; one palette is what makes it a one-line change when somebody does.

Method descriptions

bake_warning()

func bake_warning(kind: int) -> Color

The marker colour for a HammeriteMap.BakeWarningKind, for the 2D viewports and the problem browser both - the cross in the viewport and the row that selects it have to be the same colour or neither means anything.

graph_warning()

func graph_warning(kind: int) -> Color

The marker colour for a HammeriteMap.WarningKind, as bake_warning() is for the bake's.
