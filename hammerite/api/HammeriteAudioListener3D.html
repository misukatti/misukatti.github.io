HammeriteAudioListener3D

Audio. Inherits Node3D

Something in the world that can hear, as a node. Attach one to a guard.

It says which kinds of sound it cares about and how faint a sound it will still notice, and emits sound_heard when one arrives above that threshold. Everything between - working out whether the sound could reach here at all, by what route, and how much of it survived the trip - is the acoustic graph's job, and the listener never sees it. Nothing happens for types this listener has not asked for. That is the whole cost model: a footstep in a level where nothing listens for footsteps does not get propagated, or even measured.

@onready var _ears: HammeriteAudioListener3D = $Hearing
func _ready() -> void:
_ears.heard_types = [&"footstep", &"glass_break"]
_ears.sound_heard.connect(_on_sound_heard)

func _on_sound_heard(event: HammeriteAudioSoundEvent) -> void:
# Go and look where it SEEMED to come from, not where it actually was.
investigate(event.apparent_position)

Property descriptions

heard_types

var heard_types: StringName[] = []

Which sound types this listener notices. Empty means none - a listener that has not said what it is listening for is not listening, rather than listening to everything, so an unconfigured guard is deaf instead of omniscient. Assign a whole array: changing this one in place (heard_types.append(...)) does not reach the manager, which only reads the types when this is assigned or the node enters the tree.

threshold_db

var threshold_db: float = 20.0

The faintest sound this listener notices, in dB, on the same scale as HammeriteAudioSoundType.loudness_db. Sounds arriving quieter are not reported.

enabled

var enabled: bool = true

Turn hearing off without removing the node - unconscious, dead, or simply not interested yet. A disabled listener costs nothing: it is not in the routing tables at all.

ignore_own_sounds

var ignore_own_sounds: bool = true

Ignore sounds made by this node or anything under it, so a guard does not hear its own footsteps. Defaults to this listener's parent, which is normally the character it belongs to.

own_sounds_node

var own_sounds_node: Node = null

Whose noises count as this listener's own, when the parent is not the answer. A listener hung straight on a character needs nothing here. One nested inside a hearing or senses component does: its parent is that component, and the character's own footsteps are emitted from a SIBLING of it, so they arrive as somebody else's and the character startles itself every time it walks. Point this at the character and the whole of it is its own again.

ear_to_portal

var ear_to_portal: String = ""

The opening this listener has its ear pressed to, by portal name - listening at a door. What arrives through it is heard ear_gain_db louder; what comes any other way is not. Empty when the ear is not to anything.

ear_gain_db

var ear_gain_db: float = 0.0

How much louder, in dB, what comes through ear_to_portal is heard.

Method descriptions

hears_type()

func hears_type(type: StringName) -> bool

Does this listener want to hear type?

is_own_sound()

func is_own_sound(emitter: Node) -> bool

Should a sound made by emitter be ignored as this listener's own? Compares by ancestry rather than by identity: the emitter is a node under the character, and so is this listener, so "mine" means "we share an owner".
