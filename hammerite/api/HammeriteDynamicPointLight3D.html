Hammerite 3D API reference

HammeriteDynamicPointLight3D

Core: entities. Inherits HammeritePointEntityNode3D < Node3D

A baked point light that can be switched and dimmed at run time (entity type light_point_dynamic).

Baked into one of a face's four light slots rather than into the static layer, and switched by modulating that slot (HammeritePointEntityNode3D.set_light_modulation()) - every face and prop it lights follows at no cost beyond a uniform. Named or not, it runs and can be switched; a name is how something else finds it (HammeriteMap3D.trigger_named()). Extend it and override get_lit_modulation() for a flicker or a pulse. The bake picks its lights by entity type (HammeriteMap.LIGHT_TYPES), not by class, so a subclass goes into a map as the classname of the light_point_dynamic type (HammeriteEntityTypeRegistry.extend_point()); under a type of its own it is never baked, and switching it does nothing.

Property descriptions

writes_per_second

var writes_per_second: float = 30.0

How many times a second a seen light writes its brightness to what it lights, at most; zero is every frame. A write reaches every face and prop on the light's lightmaps - on a Thief mission, a dozen flickering lamps in view were 162 materials and three-quarters of a millisecond a frame - and a flame does not flicker faster than this.

Method descriptions

set_entity()

func set_entity(new_entity: HammeriteEntity) -> void

As HammeritePointEntityNode3D.set_entity(), and takes the authored enabled (default true) as the state it starts in and resets to.

get_lit_modulation()

func get_lit_modulation() -> float

How bright this light is while it is on, from 0 to 1. Override it for a light that moves - a flicker, a pulse - rather than setting the modulation after this has: the two would disagree every frame, and every surface and probe the light reaches would be told both.
